# Parts Database

One YAML file per microcontroller, in the format defined by
[`schemas/part.schema.yaml`](../schemas/part.schema.yaml). A "/" in a part
number is written as "_" in the file name. Check the whole directory with:

    python -m chipselect.parts_db parts/

## Disclaimer

**This data is not authoritative and must not be relied on for a design
without checking it against the manufacturer's current datasheet.**

- The entries were compiled by an AI model (Claude), in part by parsing
  datasheets and pin databases found online and in part from the model's own
  recall. Nobody has reviewed them against the datasheets.
- Wherever a value was filled in without a proper source, that is recorded
  per part below under "Assumed without a proper source". Four parts
  (STM32F103C8T6, STM32F103CBT6, ATMEGA328P-AU, RP2040) were written entirely
  from memory with no source consulted.
- Prices and stock levels are, at best, a single-distributor snapshot taken
  on 2026-10-11 and are already out of date. Many are unverified figures or
  invented placeholders; the table below says which. None is live data.
- The pin maps are simplified models. Each part's "Modelling notes" lists
  what was left out or approximated. In general: only ADC, DAC, SPI, I2C,
  UART, CAN, USB, RMII Ethernet, QSPI and timer PWM outputs are modelled;
  electrical limits, pin drive strength, 5 V tolerance (often omitted),
  clocking constraints and peripheral feature differences are not.
- Some datasheets were read as third-party hosted copies or older revisions
  because the manufacturer's site could not be reached. The `datasheet` URL
  in a file is where the datasheet should be found, not necessarily the copy
  that was read.

## Per-part sources and assumptions

### ATMEGA2560-16AU

- **Sources:** https://ww1.microchip.com/downloads/en/devicedoc/atmel-2549-8-bit-avr-microcontroller-atmega640-1280-1281-2560-2561_datasheet.pdf (Atmel 2549 summary datasheet, feature pages: 8 KB SRAM, 86 I/O lines, 16 MHz at 4.5-5.5 V speed grade); https://raw.githubusercontent.com/avr-rust/avr-mcu/master/packs/atmega/ATmega2560.atdf (Microchip ATDF device file: all signal-to-pin mappings for SPI, TWI, USART0-3, timers 0-5, ADC0-15, JTAG, and the ATmega2560-16AU order code's 4.5-5.5 V, 16 MHz, -40 to 85 C, TQFP100); JLCPCB parts search API https://jlcpcb.com/api/overseas-pcb-order/v1/shoppingCart/smtGood/selectSmtComponentList (part C22460: qty-1 price 13.181 USD, stock 941 on 2026-10-11).
- **Assumed without a proper source:** flash 256 KB (from memory/part name); package footprint 16 x 16 mm and 1.2 mm maximum height (standard TQFP-100 dimensions, drawing not checked); AVCC range taken equal to VCC. The file downloaded from the datasheet URL is the 38-page summary, so the pin map rests on the ATDF file rather than the full datasheet's alternate-function tables. Price and stock are JLCPCB's, a single distributor.
- **Modelling notes:** supply range is that of the 16 MHz speed grade (4.5-5.5 V), so only 5 V I/O is listed. XTAL1/XTAL2 and RESET are dedicated non-GPIO pins, so they are neither listed nor `special`. PF4-PF7 (JTAG, enabled by default fuse) are `special`; they are also ADC4-7. PG3/PG4 (TOSC2/TOSC1, optional 32 kHz timer crystal) and the ISP programming pins (PE0 PDI, PE1 PDO, PB1 SCK) are not marked special. PWM is the output-compare pins of timers 0-5; PB7 carries both OC0A and OC1C, giving 15 distinct PWM pins. USART CK is the XCKn pin; the USARTs' SPI-master mode, the external memory interface (XMEM), analog comparator and differential ADC modes are not modelled.

PB7 carries both OC0A and OC1C, and PB6 both OC1B and OC4B, giving 7 distinct PWM pins. USART1 CK (XCK1) and CTS are both on PD5; RTS is on PB7. The USART's SPI-master mode, analog comparator, and differential/gain ADC modes are not modelled. ADC channels are 0, 1, 4-13 (no ADC2/ADC3 pins on this package).

### ATSAMD21G18A-AU

- **Sources:** https://ww1.microchip.com/downloads/en/DeviceDoc/SAM-D21DA1-Family-Data-Sheet-DS40001882G.pdf (Microchip SAM D21/DA1 family datasheet rev G: Table 7-1 I/O multiplexing spot-checked, Table 7-5 list of I2C-capable pins for 48-pin devices, SWCLK/SWDIO on PA30/PA31, 1.62-3.63 V supply figure in the schematic checklist); https://raw.githubusercontent.com/modm-io/modm-devices/master/devices/sam/samd21.xml (modm-devices machine-readable pin database, generated from Microchip device files: the complete per-pin SERCOM pad, TCC/TC WO, ADC AIN, DAC and USB mapping, filtered to the G18A in the TQFP package); JLCPCB parts search API https://jlcpcb.com/api/overseas-pcb-order/v1/shoppingCart/smtGood/selectSmtComponentList (part C78624: qty-1 price 3.4512 USD, stock 3209 on 2026-10-11).
- **Assumed without a proper source:** flash 256 KB, RAM 32 KB, 48 MHz, Cortex-M0+ and the -40 to 85 C range (from memory and the task description, not re-read in the datasheet); package footprint 9 x 9 mm and 1.2 mm maximum height (standard TQFP-48 dimensions, package drawing not checked); VDDCORE range 1.1-1.3 V (from memory; nominal 1.2 V); the "3.0 V minimum for USB" remark on VDDIN (from memory); the SERCOM pad-to-signal rules (UART TX on PAD0/PAD2, RTS PAD2, CTS PAD3, XCK PAD1/PAD3; SPI DO on PAD0/2/3, SCK PAD1/3, SS PAD1/2) were written from memory of the TXPO/RXPO and DOPO/DIPO register descriptions, not re-read; the number of compare channels per TCC (4/2/2) is from memory. Price and stock are JLCPCB's, a single distributor.
- **Modelling notes:** each of the six SERCOMs is three peripherals (SERCOMn_UART, SERCOMn_SPI, SERCOMn_I2C) with the same `shares`, so the headline counts read 6 UART, 6 SPI and 6 I2C although only six serial units exist in total. SERCOM pad-combination constraints are simplified: every signal lists all pins whose pad that signal can use, but DOPO/DIPO and TXPO/RXPO permit only certain pad combinations (e.g. SPI MOSI on PAD3 forces SCK to PAD1; UART RTS/CTS force TX to PAD0 and exclude XCK), so an assignment the tool reports as valid may need a different pad set in practice. SPI signals are named for host (master) mode; NSS is the hardware-controlled SS pad, although any GPIO can serve as a software chip select. I2C is SDA = PAD0, SCL = PAD1 only on the pins of Table 7-5, so SERCOM0, 1, 4 and 5 each have a single I2C pin pair. PWM: only WO[0..3] of TCC0 and WO[0..1] of TCC1, TCC2, TC3, TC4, TC5 are listed; TCC0 WO[4..7] (PA12-PA17, PA20-PA23, PB10, PB11) and TCC1 WO[2..3] (PA08, PA09, PA24, PA25) repeat lower compare channels and are omitted, so those pins show fewer PWM options than the silicon offers. TCC1 is listed with two channels rather than four because it has only two compare channels. A TC in 32-bit mode pairs TC4 with TC5; not modelled. ADC is AIN0-7, 10, 11, 16-19 (14 pins); VREFA (PA03) and VREFB (PA04) reference roles are not modelled. DAC VOUT is PA02. USB is device/host on PA24/PA25 (also GPIO); ID, VBUS detect and SOF are not modelled. PA00/PA01 (32 kHz crystal), PA14/PA15 (main crystal) and PA30/PA31 (SWD) are `special`. Skipped: I2S, PTC touch, analog comparators, EIC, GCLK I/O. No 5 V tolerant pins.

### ESP32-C3FH4

- **Sources:** https://www.espressif.com/sites/default/files/documentation/esp32-c3_datasheet_en.pdf (ESP32-C3 Series Datasheet v2.4, downloaded; Table 1-1 variant comparison incl. 4 MB flash, -40..105 C, 22 GPIO; Tables 2-1/2-4/2-6/2-7 pin functions, ADC channels, USB pins, GPIO-matrix peripheral assignment; section 2.3.3/2.6 flash pin restrictions; Table 5-2 supply ranges; 160 MHz, 400 KB SRAM, 6 LED PWM channels). - **Assumed without a proper source:** package height_mm 0.9 (package drawing is a figure; not extracted). core string "RISC-V RV32IMC" from memory. unit_cost_usd/quantity_available from a search summary, not a fetched page. Omitted: I2S, RMT, SPI0/1 (flash), Wi-Fi/BLE radio. io_voltages 3.3 only (supplies 3.0-3.6 V). LCSC flags this part as not recommended for new designs (Espressif recommends ESP32-C3FH4X, which has only 16 GPIO bonded).
